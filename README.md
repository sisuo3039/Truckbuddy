# Truckbuddy: Talk-to-Rule transportation demo

A voice demo for transportation administrators and drivers. The same deterministic functions can run directly inside ElevenLabs hosted **Code tools** or through the included HTTP MCP server.

The original fictional rule catalogue from `demoRuleDefinitions.js` is preserved in `data/rule-definitions.ts`. Despite its original extension, that supplied file contains TypeScript interfaces.

All stock, drivers, routes, traffic and weather are **fictional**, from a fixed **2026-10-15, Europe/Berlin** snapshot. There is no live provider or transportation-system connection.

## What the demo does

- Looks up all eight original rules with source, lifecycle, exceptions and catalogue inconsistencies.
- Helps an agent ask about mandatory requirements versus preferences, scope, conditions, thresholds/units, exceptions and time-window binding.
- Returns a structured rule draft and validation report for administrator review.
- Gives drivers stock availability after reservations/quarantine, exact per-stop quantities, bins, weight, pallet positions and load order.
- Combines vehicle/resource availability, stops, delivery windows, traffic/weather scenario delays, shift availability and dispatch blockers.

Rule drafts are returned in the conversation, not stored in a durable admin system. The tools cannot publish rules, reserve stock, change routes, cancel freight orders or authorize dispatch.

## Hosted in ElevenLabs

ElevenLabs MCP integrations connect to external server URLs. Enterprise Code tools can execute this mock JavaScript on ElevenLabs infrastructure, so an external host is unnecessary for the hosted demo.

The hosted tool is `truckbuddy_transport_mock`. Its `action` parameter selects one of the 12 operations below. Source, input definitions and agent prompt are prepared locally and tested before installation. Remote resource IDs and verification state belong in a checkout-local `elevenlabs/deployment.json`, which is excluded from Git. Copy [elevenlabs/deployment.example.json](elevenlabs/deployment.example.json) when setting up your own workspace.

The original **Truckbuddy — Talk-to-Rule Demo** was installed and attached through ElevenLabs MCP. Its saved tool IDs and preserved prompt were verified, and the hosted source exactly matched the tested local bundle. Contributors should create their own demo agent or obtain access to a shared ElevenLabs workspace.

A real hosted execution/voice conversation has not been tested: the available MCP connector exposes no text-only code execution API. Local function tests and actual HTTP MCP calls passed. Open the demo agent in ElevenLabs to try the phrases below.

## Try the demo

Start with one of these phrases in the new ElevenLabs agent:

- “I’m Alex Morgan, driver D-001. What do I pick and load before my run?”
- “I’m Jamie Chen, driver D-002. Can I start my day?”
- “I’m Sam Rivera, driver D-003. Check my load and cross-dock arrival.”
- “For North Market on weekdays, deliveries must arrive before ten. Help me turn that into a rule.”
- “Show me the backload policy. Is it already approved?”

| Scenario | Expected outcome |
| --- | --- |
| D-001 / Alex Morgan | 476 cases, 10 pallet positions, 4,928 kg before packaging; 25 minutes of scenario delay; ready for dispatch review, not approved dispatch |
| D-002 / Jamie Chen | 30 produce cases short; first contractual stop 15 minutes late; dispatch blocked |
| D-003 / Sam Rivera | Planned load 75 kg over capacity; hub arrival 12 minutes after the buffered cutoff; dispatch blocked |

## Portable HTTP MCP

Requires Node.js 22 or newer.

```sh
npm install
npm run build
npm start
```

Local endpoint: `http://127.0.0.1:8787/mcp`

Health endpoint: `http://127.0.0.1:8787/health`

This stateless Streamable HTTP MCP server serves JSON responses. It listens on loopback by default. Set `PORT`/`HOST` for another deployment and `MOCK_MCP_TOKEN` to require bearer authentication. This local server is an alternative transport; the hosted ElevenLabs demo does not depend on keeping it running.

| Operation | Main input |
| --- | --- |
| `truckbuddy_demo_info` | None |
| `list_transport_rules` | Optional `query`, `stage`, `limit`, `offset` |
| `get_transport_rule` | `rule_id` |
| `prepare_rule_draft` | `spoken_requirement`, optional `draft_fields_json` |
| `validate_rule_draft` | `draft_json` |
| `get_stock` | Optional `warehouse_id`, `sku`, `date` |
| `get_resource_availability` | Optional `date` |
| `get_loading_plan` | `driver_id`, optional `date` |
| `get_driver_route` | `driver_id`, optional `date` |
| `get_traffic` | `corridor`, optional `date` |
| `get_weather` | `region`, optional `date` |
| `get_driver_day_briefing` | `driver_id`, optional `date` |

Only the fixed mock date is supported. Missing required IDs, unknown stock/regions, malformed JSON, invalid pagination and unsupported dates return actionable errors.

## Verification

```sh
npm run build
npm test
npm run check:mcp
```

Tests cover quantities, stock accounting, overload, late windows, cross-dock buffers, draft clarification, units, publication boundaries and equivalence of the hosted JavaScript bundle. The MCP check uses the official SDK client against a temporary local HTTP server to verify handshake, tools/list, real tool calls, structured results, authentication and errors.

[docs/evaluation.xml](docs/evaluation.xml) contains fixed-snapshot questions for checking an agent's tool selection and interpretation. It is a manual evaluation set, separate from automated tests.

## Demo limits

Traffic/weather delays are simply added once to each baseline stop ETA. Pallets are conservatively counted per stop/SKU without mixing deliveries. Loading weights exclude packaging. Configured shifts are fictional availability values, not jurisdiction-specific working-time compliance. This is not an optimizer or a complete policy conflict checker.

The original rule catalogue deliberately remains unchanged. R-002's tolerance never permits physical overload; R-003's shipment example has an arithmetic error; R-006's condition text omits its 20-minute buffer; R-007 needs mandatory/preferred clarification; R-008 remains unpublished. These issues are visible in tool results.
